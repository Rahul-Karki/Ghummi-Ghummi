# Backend & Database Integration Guide

This document outlines all the hardcoded mock data currently used in the frontend of the Ghummi App. When building and connecting your backend/database, you will need to replace these hardcoded values with actual API calls (e.g., using `fetch`, `axios`, or a data fetching library like React Query).

## 1. Primary Data Source (`src/data/listings.ts`)

This file is the main source of truth for the current mock data. Once the backend is connected, you can safely delete the mock arrays in this file and replace them with TypeScript interfaces that match your API response schema.

**Hardcoded Items to Replace:**

*   **`LISTINGS` Array:** Currently contains 12 mock property objects. 
    *   *Backend Action:* Replace with a `GET /api/listings` endpoint. Your database should store fields like `id`, `name`, `type`, `guests`, `price`, `rating`, and high-res image URLs.
    *   *Note:* The `match` percentage (e.g., 95%) is currently hardcoded. In a real app, this should be calculated dynamically by the backend based on user preferences.
*   **`COORDS` Object:** Contains hardcoded GPS coordinates for the map view.
    *   *Backend Action:* Ensure your database schema for a `Listing` includes `latitude` and `longitude` so this doesn't need to be maintained separately.
*   **`DECK_IMAGES` Array:** Placeholder images for the top carousel in the Gallery view.
    *   *Backend Action:* This should come from an array of image URLs associated with the "Featured" property returned by your API.

## 2. Intro Screen (`src/screens/IntroScreen.tsx`)

Several UI elements on the home screen rely on static text and data that should be dynamic.

**Hardcoded Items to Replace:**

*   **Hero Section Data:** 
    *   The location (`"San Francisco"`), dates (`"Jun 15–22"`), and guest count (`"2 guests"`) in the search bar.
    *   The greeting (`"Good Evening"`). This should be calculated dynamically based on the user's local time.
*   **`QUICK_ACTIONS` Array:** 
    *   Currently hardcodes counts like `"120+"` hotels. 
    *   *Backend Action:* The backend should return live aggregate counts of available properties per category.
*   **`CATEGORIES` Array:**
    *   While the categories themselves (Gallery, Scan, Compare) are app features and can remain static, their associated preview images currently rely on the mock `LISTINGS` array. These images should be pulled from a CMS or reliable static asset hosting.

## 3. Gallery View (`src/screens/V1GalleryScreen.tsx`)

**Hardcoded Items to Replace:**

*   **Header Context:** 
    *   Text like `"12 curated picks"` and `"San Francisco · Jun 15-22"` is hardcoded.
    *   *Backend Action:* These should be passed via React Navigation parameters based on what the user searched for on the previous screen.
*   **Initial State:**
    *   `const [selectedId, setSelectedId] = useState('oasis');`
    *   *Backend Action:* The default selected ID for the map should be the ID of the first listing returned by your API, not a hardcoded string.

## 4. Scan & Save View (`src/screens/V2ScanSaveScreen.tsx`)

**Hardcoded Items to Replace:**

*   **Header Location:** 
    *   Text like `"Barcelona · Jun 15-22 · 2 guests"` is hardcoded.
    *   *Backend Action:* Pass this context dynamically from the user's search session.

## 5. Compare View (`src/screens/V3ImageLedScreen.tsx`)

This screen relies heavily on mock comparison data.

**Hardcoded Items to Replace:**

*   **`COMPARE_DATA` Object:**
    *   Contains static arrays for thumbnails, match scores, prices, styles, locations, and reviews. 
    *   *Backend Action:* This needs to be replaced by a `GET /api/compare?ids=...` endpoint that returns side-by-side data for the properties the user selected.
*   **`WHY_MATCHED` Array:**
    *   Contains static reasons like `"Walkable to your saved spots"`.
    *   *Backend Action:* These personalization insights must be generated by the backend based on the user's profile and the property's attributes.
*   **Hero Data:**
    *   The image URL (`https://picsum.photos/...`), the title `"Cozy Den"`, and the location context `"Barcelona · Jun 15-22 · 2 guests"`.
*   **Pricing Block:**
    *   The price (`$146/night`) and total (`$1,022 · 7 nights`) are hardcoded.
    *   *Backend Action:* Calculate the total dynamically based on the listing's nightly rate and the user's selected date range.

## Recommended Steps for Integration

1.  **Define API Types:** Create a `src/types/api.ts` file and define the interfaces for `Listing`, `User`, `CompareData`, and `SearchContext` exactly as your backend will send them.
2.  **State Management:** Introduce a state manager (Zustand) or server-state manager (React Query) to handle fetching, caching, and loading states.
3.  **Replace Imports:** Go through all screens and replace `import { LISTINGS } from '../data/listings'` with your new data fetching hooks (e.g., `const { data: listings, isLoading } = useListings()`).
4.  **Add Loading States:** Build Skeleton loaders to display while the backend data is being fetched.
